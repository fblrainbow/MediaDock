# 已知限制与不支持场景（v1.0.0）

> 本文档汇总 Stage-001~010 各阶段「实际输出与计划差异」中记录的取舍。
> 每一条都是**明确的设计决定**，不是待修的缺陷；改变它们需要新的阶段评估。

---

## 1. 平台

| 限制 | 说明 | 相关决定 |
| --- | --- | --- |
| 只正式支持 YouTube | `core_platform.DEFAULT_REGISTRY` 只注册 `YouTubeAdapter`；其他 host 返回 400 `unsupported_platform` | D-013 |
| 不做 Cookie / 登录态管理 | 没有账号、Cookie UI；需要登录的内容可能失败 | 计划 §4.2 |
| 不解析播放列表 | 一次一个视频 URL；播放列表页按单个视频处理 | 计划 §4.2 |

---

## 2. 下载与格式

| 限制 | 说明 | 相关决定 |
| --- | --- | --- |
| 默认格式冻结为 1080p MP4 | 不传参数时始终使用 Stage-001 冻结表达式 | D-005 |
| 清晰度**不写入** Task/数据库 | 选择保存在服务端内存（发送期记录），服务重启后重试回落默认策略 | Stage-008 差异 1 |
| 非默认清晰度必须先探测 | `/download?preset=` 要求本进程先成功调用过 `/formats`，否则 400 `format_not_available` | Stage-008 差异 2 |
| 探测结果会过期 | `/formats` 结果按 URL 缓存在内存（上限 20 条），服务重启即清空 | Stage-008 |
| 不做「更高清晰度」承诺 | 4K/8K 未纳入验收；预设表固定为 Best/1080p/720p/480p/仅音频 | 计划 §4.2 |

---

## 3. 音频与媒体处理

| 限制 | 说明 |
| --- | --- |
| 只有三种目标 | `mp3`（默认）、`m4a`、`wav`；编码参数是服务端常量，不接受自定义码率 |
| 音频任务需要已完成的下载任务 | 源任务 `status` 必须是 `completed` 且 `type` 是 `download`，否则 409 |
| 无裁剪/归一化/变速 | 只做「整段转码」 |
| 无字幕/缩略图 | 不下载也不内嵌 |
| 输出与源文件同目录 | 输出路径 = 源文件同主名 + 目标扩展名，因此仍在 `download_dir` 内 |
| 前端不触发音频转换 | `/audio` 目前是已测的 API 契约，Userscript 不提供音频按钮 |

---

## 4. 任务、状态与存储

| 限制 | 说明 | 相关决定 |
| --- | --- | --- |
| 重启不恢复运行中任务 | `downloading`/`pending` → `error` + `error_code=interrupted`，需要手动重试 | D-012 |
| 不保存断点元数据 | 继续依赖 yt-dlp 自身的 `.part` 文件，不记录分片位置 | D-008 |
| 并发上限最大 8 | `max_active_tasks` 合法范围 1-8 | Stage-006 |
| 终态记录会按条数清理 | 保留 `purge_keep`（默认 200）条，超出按最旧清理 | D-017 |
| 无 URL/video 去重 | 对同一视频重复点下载会创建多个任务 | D-017 |
| schema v2 之后不保证向下兼容 | 降级到更旧版本可能导致旧代码读不懂新库（见 upgrade-rollback） | Stage-005 |

---

## 5. 安全与部署

| 限制 | 说明 | 相关决定 |
| --- | --- | --- |
| 默认只监听回环地址 | 需要局域网访问必须显式 `allow_lan=true`，且会记 warning | D-004 |
| 无鉴权 | 依赖「只监听 127.0.0.1」这一前提；开启 `allow_lan` 等于对局域网开放无鉴权 API | Stage-006 |
| 单实例 | 同一端口只跑一个实例（关闭端口复用）；启动时若端口被旧 MediaDock 占用会自动接管并结束旧实例 | Stage-003、Stage-011 |
| 接管会中断旧任务 | 被接管的旧实例里 `downloading`/`pending` 任务变为 `error` + `interrupted`，需手动重试 | Stage-005、Stage-011 |
| 接管依赖 PowerShell | 定位端口占用者用 `Get-NetTCPConnection`/`Get-CimInstance`；不可用时退化为退出码 2，不猜测、不乱杀 | Stage-011 |
| 不接管非 MediaDock 进程 | 端口被其他程序占用时只报告 PID/进程名/命令行，不自动结束 | Stage-011 |
| 无安装包 | 手动启动或自建快捷方式/计划任务（D-014） | D-014 |
| 无 Windows 服务 | 不注册系统服务，避免管理员权限与卸载残留 | D-014 |
| 无 Docker | 明确不在范围内 | 计划 §4.2 |
| 无自动更新 | 升级 = 替换代码 + 重启进程（见 upgrade-rollback） | Stage-010 |

## 6. 前端

| 限制 | 说明 |
| --- | --- |
| 仅 YouTube watch/shorts 页面 | `@match` 只覆盖这两类页面 |
| 无 Node.js 工具链 | 本机没有 Node.js，脚本只做结构检查（括号平衡/锚点/禁模板字符串），不做真实解析或 lint |
| 完成列表展开上限 100 行 | 更多时提示「仅显示最近 100 个，共 N 个」 |
| 面板不显示错误详情全文 | 显示错误码的中文提示；完整信息在日志与 `/events` |

---

## 7. 诊断能力边界

| 限制 | 说明 |
| --- | --- |
| `--check-config` 默认不运行 `--version` | 只有加 `--probe` 才会实际执行 yt-dlp/FFmpeg 版本探测 |
| `/health.dependencies` 不验证网络 | 不确认 YouTube 可达，只确认依赖可执行 |
| 发布检查离线 | `tests/release_check.py` 用脚本化子进程，不访问网络，因此不能替代人工真实下载验证 |
